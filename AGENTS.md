# Repository maintenance

Read README.md first.

Generated by the private portfolio-suite authoring project. Its content/, src/, public/ and exports/ inputs produce dist/ through scripts/build_site.py. scripts/check_site.py validates that output. The release-site checkout publishes reviewed output on codex/portfolio-suite. These commands belong in the authoring workspace, not this publication clone.

Treat published HTML, assets and downloads as generated output. Make content changes in the owning authoring project, then copy only reviewed public artifacts. Keep these repository-level maintenance documents when refreshing generated output.

Before a change, inspect the current branch, remote and working tree. Preserve other contributors’ changes. Do not publish private authoring notes, machine paths, correspondence or raw research.

For documentation changes, check Markdown links and git diff --check. For page or asset changes, preview the affected route, test its links and downloads, then check the deployed URL after publication. A successful Git push does not prove a Pages deployment succeeded. Preserve the previous commit for a normal revert; do not rewrite history.
